# 📖 Инструкция по использованию Генератора учебных проектов

## Для кого эта инструкция

Эта инструкция предназначена для преподавателей, методистов и всех, кто создает учебные проекты для Школы 21. Вы узнаете, как использовать веб-интерфейс генератора для создания качественных README-файлов для ваших проектов.

**Не нужно быть программистом** — интерфейс простой и интуитивный. Мы объясним каждый шаг подробно.

---

## 🚀 Быстрый старт: что делает генератор

**Генератор учебных проектов** — это инструмент, который создает полный README-файл для учебного проекта автоматически. Вместо того чтобы писать документ вручную, вы:

1. **Заполняете форму** с параметрами проекта (название, описание, навыки и т.д.)
2. **Нажимаете кнопку "Сгенерировать"**
3. **Ждете 5-15 минут** (система работает автоматически)
4. **Получаете готовый README** с теорией, практикой, критериями оценки

**Что входит в готовый README:**
- Введение и инструкция для студентов
- Теоретическая часть с объяснениями
- Практические задания (от 2 до 8 задач)
- Критерии оценки выполнения
- Бонусные задания (опционально)
- Чек-листы для проверки

---

## 🏠 Вход в систему и главное меню

### Как войти

1. Откройте браузер (Chrome, Firefox, Edge или Safari)
2. Перейдите по адресу приложения (вам предоставят ссылку)
3. Введите **логин** и **пароль**
4. Нажмите кнопку **"Войти"**

После входа вы увидите главное меню с двумя большими карточками.

### Главное меню: выбор режима работы

На главном экране вы увидите две карточки:

#### 🚀 Генерация README

**Что это:** Создание нового учебного проекта с нуля.

**Когда использовать:** Когда вам нужно создать новый проект — система сгенерирует весь README автоматически.

**Что получите:** Полный README-файл с теорией, практикой, критериями оценки, готовый к использованию.

**Кнопка:** **"Перейти к генератору"** — открывает форму для создания проекта.

#### ✅ Проверка README

**Что это:** Проверка уже готового README-файла на соответствие стандартам.

**Когда использовать:** Когда у вас уже есть готовый README и нужно проверить его качество.

**Что получите:** Подробный отчет о том, что хорошо, а что нужно улучшить, с конкретными рекомендациями.

**Кнопка:** **"Перейти к проверке"** — открывает форму для загрузки и проверки README.

## 📝 Режим генерации README: подробная инструкция

### Общий вид экрана

Экран генерации разделен на **две колонки**:

- **Левая колонка** — форма с параметрами проекта (здесь вы заполняете данные)
- **Правая колонка** — результаты генерации (появляется после запуска, показывает прогресс и итоговый результат)

Сначала правая колонка пустая — она заполнится после того, как вы запустите генерацию.

---

### 📋 Левая колонка: заполнение параметров проекта

#### 1. Загрузка готового файла (опционально, но удобно!)

**Где находится:** В самом верху формы, первое поле.

**Что это:** Вместо заполнения формы вручную, вы можете загрузить готовый файл Excel или JSON со всеми параметрами проекта. Это особенно удобно, если у вас много проектов или вы работаете в команде.

**Как использовать:**

1. Нажмите на область **"📁 Нажмите для загрузки файла"**
2. В открывшемся окне выберите файл `.xlsx` (Excel) или `.json`
3. Файл загрузится, и форма автоматически заполнится всеми данными из файла

**Кнопка "📥 Скачать шаблон Excel":**

- Нажмите эту кнопку, чтобы скачать пустой шаблон Excel
- Заполните шаблон в Excel (все поля подписаны)
- Сохраните файл
- Загрузите его обратно — форма заполнится автоматически

**Когда это полезно:**
- У вас есть таблица с проектами в Excel
- Вы хотите подготовить несколько проектов заранее
- Вы работаете в команде и передаете проекты друг другу

**Важно:** Если вы загрузили файл, все поля ниже заполнятся автоматически. Вы можете их изменить, если нужно.

---

#### 2. Базовые параметры проекта

Это основная информация о вашем проекте. Чем больше полей вы заполните, тем лучше будет результат генерации.

##### Язык

**Где находится:** Первое поле в разделе "Базовые параметры".

**Что это:** Язык, на котором будет создан README.

**Как заполнить:**
- Откройте выпадающий список
- Выберите нужный язык:
- `ru` — русский
- `en` — английский
- `kg` — киргизский
- `uz` — узбекский

**Важно:** Это поле **обязательное** — без него генерация не запустится.

---

##### Тип проекта

**Где находится:** Второе поле в разделе "Базовые параметры".

**Что это:** Для скольких студентов предназначен проект — для одного или для команды.

**Как заполнить:**
- Откройте выпадающий список
- Выберите:
- **"индивидуальный"** — проект для одного студента
- **"групповой"** — проект для команды студентов

**Важно:** Это поле **обязательное**.

**Что происходит, если выбрать "групповой":**

После выбора "групповой" появится дополнительное поле:

**"Количество человек в группе"** — введите число от 2 до 10.

Система автоматически создаст роли для каждого участника группы и распределит задачи между ними.

---

##### Тематический блок

**Где находится:** Третье поле в разделе "Базовые параметры".

**Что это:** Направление обучения, к которому относится ваш проект. Это помогает системе понять контекст и создать более подходящий контент.

**Как заполнить:**
- Откройте выпадающий список
- Выберите нужный тематический блок:
  - **BSA** — Бизнес-аналитика
- **Cb** — Кибербезопасность
- **DO** — DevOps
- **PjM** — Проектный менеджмент
- **QA** — Тестирование и обеспечение качества
- **DS** — Машинное обучение
  - **ADD** — Добавить новый тематический блок

**Важно:** Это поле **обязательное**.

**Если выбранного блока нет в списке:**

Если вы выбрали **"ADD" (Добавить новый)**, появится раскрывающийся блок с полями:

1. **"Название тематического блока"** — введите полное название, например: "Машинное обучение"
2. **"Кодовое обозначение"** — введите короткое обозначение на латинице, например: "ML"
3. Нажмите кнопку **"Добавить тематический блок"**

После этого новый блок появится в списке и будет доступен для использования.

---

##### Уровень аудитории

**Где находится:** Четвертое поле в разделе "Базовые параметры".

**Что это:** Для студентов какого уровня сложности предназначен проект. Это помогает системе определить сложность заданий и глубину теоретического материала.

**Как заполнить:**
- Введите текстом уровень сложности
- Примеры: "Начальный", "Средний", "Продвинутый", "Для новичков", "Базовый уровень"

**Что происходит:** Система использует эту информацию, чтобы:
- Определить количество практических задач (для начинающих больше простых задач, для продвинутых — меньше, но сложнее)
- Настроить сложность теоретического материала
- Выбрать подходящие примеры и объяснения

**Совет:** Будьте конкретны. "Для новичков" лучше, чем просто "Начальный".

---

##### Название проекта

**Где находится:** Пятое поле в разделе "Базовые параметры".

**Что это:** Название вашего учебного проекта. Оно будет использовано в заголовке README.

**Как заполнить:**
- Введите название проекта
- Примеры: "Система управления паролями", "Веб-приложение для заметок", "Анализ данных с помощью Python"

**Что происходит:** Система использует название для:
- Создания заголовка README
- Понимания тематики проекта
- Поиска похожих проектов в базе знаний

**Совет:** Используйте конкретные, понятные названия. Избегайте слишком общих формулировок.

---

##### Обязательные инструменты

**Где находится:** Шестое поле в разделе "Базовые параметры".

**Что это:** Технологии, инструменты и библиотеки, которые студенты должны использовать в проекте.

**Как заполнить:**
- Перечислите инструменты через запятую
- Примеры: `Python, Flask, SQLite, Git` или `JavaScript, React, Node.js, MongoDB`
- Пробелы не обязательны, но можно ставить для читаемости

**Что происходит:** Система:
- Включит эти инструменты в описание проекта
- Создаст примеры кода с использованием этих технологий
- Добавит инструкции по установке и настройке
- Упомянет инструменты в практических заданиях

**Совет:** Указывайте конкретные версии, если это важно (например: "Python 3.9", "React 18").

---

##### Краткое описание проекта

**Где находится:** Седьмое поле в разделе "Базовые параметры" (многострочное текстовое поле, 4 строки).

**Что это:** Краткое описание того, что должен делать проект, какую проблему решать.

**Как заполнить:**
- Опишите суть проекта в нескольких предложениях
- Укажите основную функциональность
- Пример:
```
Создать веб-приложение для управления заметками.
Пользователь может создавать, редактировать и удалять заметки.
Данные хранятся в базе данных SQLite.
  Приложение должно иметь простой и понятный интерфейс.
  ```

**Что происходит:** Система использует описание для:
- Создания введения в README
- Понимания целей проекта
- Генерации практических заданий, которые соответствуют описанию

**Совет:** Чем подробнее описание, тем точнее будут задания. Укажите ключевые функции и требования.

---

##### Образовательные результаты

**Где находится:** Восьмое поле в разделе "Базовые параметры" (многострочное текстовое поле, 5 строк).

**Что это:** Что студент должен **узнать** или **понять** после выполнения проекта. Это знания и понимание концепций.

**Как заполнить:**
- Перечислите образовательные результаты, по одному в строке
- Используйте формулировки типа "Понимание...", "Знание...", "Представление о..."
- Пример:
```
Понимание работы с базами данных
  Знание принципов REST API
  Понимание архитектуры веб-приложений
  Представление о работе с аутентификацией
  ```

**Что происходит:** Система:
- Создает теоретическую часть, которая объясняет эти концепции
- Формирует практические задания, которые помогают освоить эти знания
- Проверяет, что все образовательные результаты покрыты в проекте

**Важно:** Образовательные результаты — это про **знания** (что студент должен знать). Навыки (что студент должен уметь делать) указываются в следующем поле.

**Совет:** Используйте формулировки из образовательных стандартов, если они у вас есть.

---

##### Получаемые навыки

**Где находится:** Девятое поле в разделе "Базовые параметры" (многострочное текстовое поле, 5 строк).

**Что это:** Практические навыки, которые студент получит, выполняя проект. Это умения и способности применять знания на практике.

**Как заполнить:**
- Перечислите навыки, по одному в строке
- Используйте формулировки типа "Умение...", "Навык...", "Способность..."
- Пример:
```
Работа с Flask
Создание REST API
Работа с SQLite
Версионирование кода в Git
  Настройка окружения разработки
  ```

**Что происходит:** Система:
- Создает практические задания, которые развивают эти навыки
- Добавляет примеры кода и инструкции по использованию инструментов
- Проверяет, что все навыки отрабатываются в проекте

**Важно:** Навыки — это про **умения** (что студент должен уметь делать). Знания указываются в предыдущем поле.

**Совет:** Будьте конкретны. "Работа с Flask" лучше, чем просто "Веб-разработка".

---

#### 3. Настройки репозитория (раскрывающийся блок)

**Где находится:** После полей "Базовые параметры", блок с заголовком "⚙️ Настройки репозитория (для ожидаемого результата)".

**Что это:** Настройки для создания ссылок на файлы в репозитории GitHub. Если у вас есть репозиторий проекта, эти настройки помогут системе создать правильные ссылки.

**Как открыть:** Нажмите на заголовок блока — он раскроется, и вы увидите два поля.

**Когда использовать:** Если у вас уже есть репозиторий GitHub для проекта или вы знаете, где он будет размещен.

##### Базовый URL репозитория (опционально)

**Что это:** Адрес вашего репозитория на GitHub.

**Как заполнить:**
- Введите полный URL репозитория
- Пример: `https://github.com/school21/project-name`

**Что происходит:** Если указан URL, система:
- Создаст ссылки на файлы в репозитории
- Добавит инструкции по клонированию репозитория
- Включит ссылки в примеры кода и инструкции

**Важно:** Это поле необязательное. Если репозитория еще нет, можно оставить пустым.

---

##### Шаблон пути в репозитории (опционально)

**Что это:** Шаблон того, как организованы файлы в вашем репозитории. Система использует его для создания ссылок на конкретные файлы.

**Как заполнить:**
- Введите шаблон пути
- По умолчанию: `repo/part-03/task-{num:02d}/README.md`

**Что означает шаблон:**
- `{num:02d}` — это место, где будет подставлен номер задачи
- `02d` означает, что номер будет с ведущим нулем (01, 02, 03...)
- Пример результата: `repo/part-03/task-01/README.md`, `repo/part-03/task-02/README.md`

**Как изменить под свою структуру:**
- Если ваши задачи лежат в `tasks/task-1/`, используйте: `tasks/task-{num}/README.md`
- Если структура другая, просто замените шаблон на нужный

**Важно:** Это поле необязательное. Если не знаете структуру репозитория, можно оставить значение по умолчанию или оставить пустым.

---

#### 4. Бонусное задание

**Где находится:** После блока "Настройки репозитория", чекбокс "Генерировать бонусное задание".

**Что это:** Дополнительное задание повышенной сложности для студентов, которые хотят получить больше опыта или дополнительные баллы.

**Как использовать:**
- Поставьте галочку в чекбоксе, если хотите добавить бонусное задание
- Если галочка стоит, появится дополнительное поле

**Дополнение к бонусному заданию (опционально):**

Если вы отметили чекбокс, появится текстовое поле, где можно указать:
- Специфические требования к бонусу
- Дополнительные условия
- Особые критерии оценки

**Пример:** "Бонусное задание должно использовать технологии, не изученные в основном курсе" или "Добавить возможность экспорта данных в Excel".

**Что происходит:** Система создаст отдельный раздел "Бонус" в README с заданием повышенной сложности.

**Совет:** Бонусные задания мотивируют продвинутых студентов и дают им возможность проявить себя.

---

#### 5. P2P-критерии практических задач

Отдельные чек-листы больше не настраиваются в форме. Проверяемые P2P-критерии формируются внутри каждой практической задачи и проходят общие проверки качества практического блока.

---

#### 7. Дополнительные настройки (раскрывающийся блок)

**Где находится:** В самом низу формы, блок с заголовком "Дополнительные настройки".

**Что это:** Дополнительные опции для улучшения качества генерации.

**Как открыть:** Нажмите на заголовок блока — он раскроется.

##### Контекст учебного плана

**Что это:** Контекст проекта из учебного плана. Система использует его для понимания позиции проекта в программе и создания более релевантного контента.

**Как использовать:**
1. Нажмите на область **"📁 Нажмите для загрузки файлов"**
2. В открывшемся окне выберите один или несколько файлов `.md` (можно выбрать несколько файлов, удерживая Ctrl или Cmd)
3. Файлы загрузятся, но production-контекст берется из учебного плана

**Что учитывается:**
- Специфика трека
- Правильная терминология
- Позиция проекта относительно предыдущих и следующих проектов
- Преемственность навыков и образовательных результатов
- Подходящие примеры и объяснения

**Какие файлы загружать:**
- README-файлы из похожих проектов вашего трека
- Документы с описанием методологии вашего направления
- Примеры хороших проектов, которые вы хотите использовать как образец

**Совет:** Проверяйте, что выбранный проект связан с актуальным учебным планом. Это сильнее влияет на качество генерации, чем загрузка произвольных файлов.

---

### 🔘 Кнопки управления (левая колонка)

В левой колонке, внизу формы, находятся кнопки для управления процессом генерации.

#### 🗑️ Очистить форму

**Где находится:** Внизу левой колонки, первая кнопка.

**Что делает:** Очищает все поля формы, возвращая их к пустому состоянию.

**Когда использовать:** Когда вы хотите начать заполнение заново с чистого листа.

**Важно:** Это действие нельзя отменить — все введенные данные будут удалены.

---

#### 🗑️ Очистить генерацию

**Где находится:** Внизу левой колонки, вторая кнопка.

**Что делает:** Очищает результаты генерации в правой колонке, но не трогает заполненную форму.

**Когда использовать:** Когда вы хотите скрыть результаты, но сохранить заполненную форму (например, чтобы запустить генерацию заново с теми же параметрами).

**Важно:** Результаты генерации сохраняются в браузере, так что при необходимости их можно восстановить.

#### 🚀 Сгенерировать

**Где находится:** Внизу левой колонки, большая кнопка (обычно выделена цветом).

**Что это:** Главная кнопка для запуска генерации контента.

**Что происходит при нажатии:**

1. **Проверка данных** — система проверяет, что все обязательные поля заполнены
2. **Отправка на сервер** — все данные из формы отправляются на сервер
3. **Запуск генерации** — начинается процесс создания README (это занимает 5-15 минут)
4. **Отображение прогресса** — в правой колонке появляется область с логами генерации:
   - ⏱️ **Время работы** — таймер показывает, сколько времени прошло с начала генерации
   - 🤖 **Текущий агент** — название этапа, который выполняется сейчас (например: "Phase 2 · Theory", "Phase 3 · Practice")
5. **Завершение** — после завершения генерации результаты появятся в правой колонке

**Важно:**
- Генерация может занять **до 15 минут** — это нормально, не закрывайте страницу!
- Во время генерации кнопка становится неактивной и показывает "⏳ Генерация..."
- Не закрывайте страницу до завершения генерации
- Результаты сохраняются автоматически в браузере

**Что делать во время генерации:**
- Следите за прогрессом в правой колонке
- Обратите внимание на предупреждения, если они появляются
- Не закрывайте страницу — процесс продолжится, но вы не увидите прогресс

**После завершения:** Результаты появятся в правой колонке, и вы сможете их просмотреть, скачать или перегенерировать.

#### ⬅ Главное меню

**Где находится:** Внизу левой колонки, кнопка со стрелкой влево.

**Что делает:** Возвращает на экран выбора режима (генерация или проверка).

**Важно:** Результаты генерации сохраняются в браузере, при возврате они не потеряются. Вы можете вернуться к результатам позже.

**Где находится:** Внизу левой колонки, последняя кнопка.

**Что делает:** Выходит из системы и возвращает на экран входа.

**Важно:** После выхода нужно будет войти заново. Результаты генерации сохраняются в браузере, но для доступа к ним нужно будет снова войти в систему.

#### 🔄 Перегенерация контента

**Где находится:** В правой колонке, после области предупреждений, блок "Перегенерация контента".

**Что это:** Возможность изменить уже сгенерированный README без полной перегенерации всего проекта. Это быстрее и удобнее, чем генерировать проект заново.

**Когда использовать:**
- Вам нужно изменить только часть README (например, добавить больше примеров кода)
- Вы хотите исправить что-то на основе комментариев из проверки критериев
- Нужно улучшить конкретный раздел без изменения всего документа

**Как использовать:**

1. **Поле "Комментарии по изменению README"**
   - Опишите, что нужно изменить
   - Будьте конкретны: "Добавь больше примеров кода в раздел про базы данных", "Упрости описание задачи 3", "Добавь диаграмму в теоретическую часть"
   - Чем подробнее описание, тем точнее будут изменения

2. **Кнопка "✍️ Вставить шаблон комментариев"**
   - Нажмите эту кнопку, чтобы вставить готовый шаблон комментариев
   - Шаблон содержит примеры того, как можно описать изменения
   - Используйте шаблон как основу и измените под свои нужды

   - Эта кнопка появляется после того, как вы просмотрели критерии оценки (вкладка "Метрики")
   - Нажмите её, чтобы автоматически заполнить комментарии на основе критериев, которые не прошли проверку
   - Это очень удобно для быстрого исправления проблем — система сама сформулирует, что нужно улучшить

4. **Кнопка "🔄 Перегенерировать"**
   - После того как вы описали изменения, нажмите эту кнопку
   - Система запустит перегенерацию с учетом ваших комментариев
   - Процесс займет меньше времени, чем полная генерация (обычно 2-5 минут)

5. **Кнопка "🗑️ Очистить перегенерацию"**
   - Очищает поле комментариев и результаты перегенерации
   - Используйте, если хотите начать перегенерацию заново

**После перегенерации:**
- Появится блок "📝 Что было изменено:" с описанием всех изменений
- В вкладках "Метрики" и "Отчет" появятся переключатели между оригинальной и перегенерированной версиями
- Вы сможете сравнить результаты и выбрать, какая версия лучше

**Совет:** Используйте перегенерацию для точечных улучшений. Это быстрее и эффективнее, чем генерировать весь проект заново.

## ❓ Часто задаваемые вопросы о генерации

### Общие вопросы

**Q: Сколько времени занимает генерация?**

A: Обычно от 5 до 15 минут. Это зависит от:
- Сложности проекта
- Количества практических заданий
- Наличия дополнительных материалов (формулы, диаграммы)
- Загруженности сервера

**Важно:** Не закрывайте страницу во время генерации! Процесс можно отслеживать в реальном времени.

---

**Q: Что делать, если генерация зависла?**

A: 
- Генерация может занимать до 15 минут — это нормально
- Проверьте, что таймер продолжает идти (в правой колонке)
- Проверьте, что текущий агент меняется (название этапа обновляется)
- Если прошло больше 20 минут без изменений:
  1. Проверьте консоль браузера (F12 → вкладка Console) на ошибки
  2. Обновите страницу (F5)
  3. Результаты сохраняются в браузере, при обновлении они восстановятся

---

**Q: Можно ли закрыть страницу во время генерации?**

A: 
- Технически можно, но **не рекомендуется**
- Результаты сохраняются в браузере (sessionStorage)
- При возврате на страницу генерация может продолжиться, если она еще идет
- Если генерация завершилась, результаты восстановятся автоматически
- Но вы не увидите прогресс, если закроете страницу

**Рекомендация:** Дождитесь завершения генерации, чтобы видеть прогресс и сразу получить результаты.

---

**Q: Что делать, если появилась ошибка?**

A:
1. Прочитайте сообщение об ошибке внимательно
2. Проверьте консоль браузера (F12 → вкладка Console) для подробностей
3. Проверьте, что все обязательные поля заполнены:
   - Язык
   - Тип проекта
   - Тематический блок
4. Попробуйте обновить страницу (F5)
5. Если ошибка повторяется, проверьте:
   - Правильно ли указаны параметры
   - Есть ли подключение к интернету
   - Работает ли сервер (обратитесь к администратору)

---

**Q: Как сохранить результаты?**

A:

## ✅ Режим проверки README

### Что это такое?

**Проверка README** — это инструмент для анализа уже готового README-файла на соответствие стандартам Школы 21. Если у вас уже есть готовый проект (созданный вручную или сгенерированный ранее), вы можете загрузить его и получить подробный отчет о качестве.

**Зачем это нужно:**
- Убедиться, что README соответствует всем стандартам Школы 21
- Найти проблемы и недочеты до того, как проект попадет к студентам
- Получить конкретные рекомендации по улучшению
- Проверить соответствие образовательным результатам (ЗУН)

**Когда использовать:**
- После создания README вручную
- После генерации, чтобы убедиться в качестве
- Перед финальной отправкой проекта студентам
- При обновлении существующего проекта

---

### Общий вид экрана

Экран проверки, как и экран генерации, разделен на **две колонки**:

- **Левая колонка** — загрузка README и настройки проверки
- **Правая колонка** — результаты проверки (появляется после запуска)

Сначала правая колонка показывает сообщение: "Загрузите README и нажмите «Проверить», чтобы увидеть результаты."

---

### 📋 Левая колонка: входные данные

#### Загрузка README.md

**Где находится:** В самом верху левой колонки, первое поле.

**Что это:** Поле для загрузки файла README, который нужно проверить.

**Как использовать:**
1. Нажмите на область **"📁 Нажмите для загрузки README.md"**
2. В открывшемся окне выберите файл с расширением `.md`
3. Файл загрузится, и под кнопкой появится имя файла

**Важно:**
- Поддерживаются только файлы с расширением `.md` (Markdown)
- Файл должен быть в формате Markdown
- Размер файла не должен быть слишком большим (обычно до 1-2 МБ)

**Что происходит после загрузки:**
- Имя файла отображается под кнопкой загрузки
- Файл сохраняется в памяти браузера
- Кнопка "✅ Проверить README" становится активной

**Совет:** Убедитесь, что файл действительно является README и содержит весь необходимый контент перед загрузкой.

---

#### Образовательные результаты (опционально, раскрывающийся блок)

**Где находится:** После поля загрузки README, блок с заголовком "Образовательные результаты (опционально)".

**Что это:** Поле для указания образовательных результатов проекта. Это помогает системе более точно проверить соответствие README образовательным целям.

**Как открыть:** Нажмите на заголовок блока — он раскроется, и вы увидите текстовое поле.

**Как заполнить:**
- Введите образовательные результаты, по одному в строке
- Используйте формулировки типа "Понимание...", "Знание...", "Представление о..."
- Пример:
```
Понимание работы с базами данных
  Знание принципов REST API
  Понимание архитектуры веб-приложений
  ```

**Зачем это нужно:**
- Система проверяет, соответствует ли README указанным образовательным результатам
- Критерии проверки по ЗУН (знания, умения, навыки) становятся более точными
- Вы получаете более релевантные комментарии и рекомендации

**Важно:** Это поле **необязательное**, но его заполнение значительно улучшает качество проверки. Рекомендуется заполнять, если у вас есть эта информация.

**Совет:** Если у вас есть спецификация проекта с образовательными результатами, скопируйте их сюда — это займет всего минуту, но улучшит качество проверки.

---

#### ✅ Проверить README

**Где находится:** После блока с образовательными результатами, большая кнопка.

**Что это:** Главная кнопка для запуска проверки README.

**Что происходит при нажатии:**

1. **Проверка файла** — система проверяет, что файл загружен
2. **Отправка на сервер** — README и образовательные результаты (если указаны) отправляются на сервер
3. **Запуск проверки** — начинается анализ README по всем критериям (это занимает несколько минут)
4. **Отображение результатов** — после завершения результаты появляются в правой колонке

**Важно:**
- Проверка занимает **несколько минут** (обычно 2-5 минут) — это нормально
- Во время проверки кнопка становится неактивной и показывает "⏳ Проверка..."
- Не закрывайте страницу до завершения проверки
- Результаты сохраняются в браузере автоматически

**Что делать во время проверки:**
- Подождите — процесс идет автоматически
- Не закрывайте страницу
- Результаты появятся автоматически после завершения

**После завершения:** В правой колонке появятся результаты проверки с подробным анализом.

#### ⬅ Вернуться к выбору режима

**Где находится:** Внизу левой колонки, кнопка со стрелкой влево.

**Что делает:** Возвращает на главное меню выбора режима (генерация или проверка).

**Важно:** Результаты проверки сохраняются в браузере, при возврате они не потеряются. Вы можете вернуться к результатам позже.

---

#### 🗑️ Очистить результат

**Где находится:** Внизу левой колонки, рядом с кнопкой "Вернуться к выбору режима".

**Что делает:** Очищает результаты проверки в правой колонке, но не удаляет загруженный файл.

**Когда использовать:** Когда вы хотите проверить другой README или начать проверку заново.

**Важно:** Кнопка появляется только после успешной проверки. Если вы хотите проверить другой файл, просто загрузите новый — старые результаты заменятся новыми.

##### 📈 Критерии

**Что показывает:** Детальную оценку README по всем 39 критериям рубрики Школы 21. Это самая важная вкладка — здесь вы увидите, что хорошо, а что нужно улучшить.

**Что можно увидеть:**

**Таблица со всеми критериями:**
- Каждый критерий в отдельной строке

**Оценка по каждому критерию:**
- ✅ **Пройден** — критерий выполнен, всё хорошо
- ❌ **Не пройден** — критерий не выполнен, нужно улучшить

**Комментарии к каждому критерию:**
- **Что хорошо** — что уже сделано правильно

**Категории критериев:**
Критерии разделены на категории:

3. **Прочитайте комментарии** к каждому непройденному критерию:
   - Что именно не так
   - Почему это важно

   - Откройте README в вашем редакторе
   - Внесите изменения согласно рекомендациям
   - Сохраните файл

6. **Повторяйте** до тех пор, пока все критерии не будут пройдены

**Совет:** Не пытайтесь исправить всё сразу. Начните с критериев, которые помечены как критичные или важные. После исправлений проверьте снова — обычно после 1-2 итераций все критерии проходят проверку.

**Важно:** Стремитесь к тому, чтобы все критерии были пройдены. Это гарантирует, что README соответствует стандартам Школы 21 и готов к использованию.

##### 📝 Статистика текста

**Что показывает:** Детальную статистику и анализ текста README — количественные метрики документа.

**Что можно увидеть:**

**Общая статистика:**
- **Количество слов** — общий объем текста

- **Количество строк** — сколько строк в файле

**Статистика по заголовкам:**
- **Количество заголовков каждого уровня:**
  - H1 (заголовок первого уровня) — обычно один, название проекта
  - H2 (заголовок второго уровня) — основные разделы (Глава 1, Глава 2...)
  - H3 (заголовок третьего уровня) — подразделы
  - H4 и ниже — более мелкие разделы
- **Структура документа** — какие разделы есть в README

**Анализ читаемости:**
- **Средняя длина предложений** — сколько слов в среднем в предложении
- **Сложность текста** — оценка сложности для чтения
- **Оценка читаемости** — общая оценка того, насколько легко читать текст

**Информация о форматировании:**
- **Количество списков** — маркированных и нумерованных
- **Количество таблиц** — сколько таблиц в документе
- **Количество блоков кода** — сколько примеров кода
- **Количество ссылок** — сколько ссылок на внешние ресурсы

**Как использовать:**
- **Просмотрите общую статистику** — это поможет понять объем документа
- **Проверьте структуру заголовков:**
  - Должна быть логичная иерархия (H1 → H2 → H3)
  - Не должно быть пропусков уровней (например, H1 сразу после H3)
  - Количество заголовков должно быть разумным (не слишком много, не слишком мало)
- **Обратите внимание на читаемость:**
  - Средняя длина предложений не должна быть слишком большой (оптимально 15-20 слов)
  - Если предложения слишком длинные, текст может быть сложным для чтения
- **Проверьте разнообразие форматирования:**
  - Должны быть списки, таблицы, блоки кода
  - Это делает документ более структурированным и понятным

**Совет:** Используйте статистику как дополнительный инструмент оценки. Если метрики показывают проблемы (например, слишком длинные предложения), это может указывать на то, что текст нужно упростить.

## ✨ Улучшение README

### Что это такое?

**Улучшение README** — это инструмент для автоматического улучшения уже существующего README-файла. Система извлекает данные из вашего README, анализирует его структуру и содержание, а затем генерирует улучшенную версию, соответствующую всем стандартам Школы 21.

**Зачем это нужно:**
- Ваш README не соответствует стандартам Школы 21 (низкая оценка по критериям)
- Нужно улучшить структуру и содержание без полной переработки
- Хотите автоматически привести README к единому стандарту
- Нужно дополнить README недостающими разделами или улучшить существующие

**Когда использовать:**
- После проверки README, если оценка низкая (менее 70%)
- Когда нужно быстро улучшить качество документа
- При необходимости привести README к стандартам Школы 21
- Когда нужно дополнить README недостающими элементами (теория, практика, критерии)

**Как это работает:**
1. Система извлекает данные из вашего README (название, описание, навыки, инструменты и т.д.)
2. Вы можете отредактировать извлеченные данные в модальном окне
3. Система генерирует улучшенную версию README с учетом всех стандартов
4. Вы получаете улучшенный README, критерии оценки и сравнение с оригиналом

---

### Как запустить улучшение README

#### Шаг 1: Проверка README

**Важно:** Улучшение README доступно только после проверки. Сначала выполните проверку README (см. раздел "✅ Режим проверки README").

**После проверки:**
- В правой колонке появится кнопка **"✨ Улучшить README"**
- Если оценка по критериям менее 70%, появится предупреждение с рекомендацией использовать улучшение
- Кнопка доступна всегда, независимо от оценки

#### Шаг 2: Запуск улучшения

**Где находится:** В правой колонке, после области предупреждений, кнопка **"✨ Улучшить README"**.

**Что происходит при нажатии:**

1. **Извлечение данных** — система автоматически извлекает данные из вашего README:
   - Название проекта
   - Описание
   - Образовательные результаты (Learning Outcomes)
   - Навыки (Skills)
   - Инструменты и технологии
   - Количество практических задач
   - Язык проекта
   - Тематический блок
   - Уровень аудитории
   - Тип проекта (индивидуальный/групповой)

2. **Открытие модального окна** — появляется модальное окно "✏️ Редактирование данных для улучшения README"

3. **Заполнение формы** — все извлеченные данные автоматически заполняются в форму

**Важно:**
- Извлечение данных занимает несколько секунд
- Если система не может извлечь какие-то данные, поля останутся пустыми — их можно заполнить вручную
- Если нет связи с LLM, поля будут пустыми — заполните их вручную

### Как система определяет данные

Система использует несколько методов для извлечения данных из README:

#### 1. Прямое извлечение

**Что это:** Система ищет специальные разделы в README, где информация указана явно.

**Примеры:**

- Раздел "Инструменты" или "Technologies"
- Заголовок H1 обычно содержит название проекта

**Как это работает:** Система анализирует структуру README и находит разделы с нужной информацией.

---

#### 2. Анализ содержания

**Что это:** Система анализирует текст README и определяет информацию на основе содержания.

**Примеры:**
- **Образовательные результаты** — система ищет формулировки типа "студент должен понять", "необходимо знать", "важно понимать"
- **Навыки** — система ищет формулировки типа "студент научится", "получит навык", "сможет делать"
- **Инструменты** — система ищет упоминания технологий (Python, Flask, SQLite и т.д.)
- **Количество задач** — система подсчитывает практические задания в разделе "Практика" или "Глава 3"

**Как это работает:** Система использует языковую модель для анализа текста и определения, что является образовательным результатом, а что — навыком.

---

#### 3. Классификация проекта

**Что это:** Система определяет параметры проекта на основе анализа всего README.

**Что определяется:**
- **Язык проекта** — анализируется язык текста (русский, английский, киргизский, узбекский)
- **Тематический блок** — сравнивается содержание с известными тематическими блоками:
  - Сначала система проверяет по ключевым словам
  - Если не находит совпадений, использует языковую модель для классификации
  - Может предложить новый тематический блок, если проект не соответствует существующим
- **Уровень аудитории** — анализируется сложность материала:
  - Простые объяснения и базовые концепции → "Начальный"
  - Средняя сложность → "Средний"
  - Сложные концепции и продвинутые темы → "Продвинутый"
- **Тип проекта** — анализируется, есть ли упоминания о групповой работе или индивидуальной

**Как это работает:** Система использует комбинацию ключевых слов и языковой модели для классификации проекта.

---

#### 4. Валидация и исправление

**Что это:** Система проверяет извлеченные данные и исправляет ошибки.

**Что проверяется:**
- Все ли важные поля заполнены
- Корректны ли значения (например, количество задач — это число)
- Нет ли противоречий (например, язык проекта соответствует языку текста)
- Соответствует ли формат данных ожидаемому

**Автоматические исправления:**
- Если найдены дубликаты, они удаляются
- Если формат не соответствует ожидаемому, он корректируется
- Если данные неполные, система пытается дополнить их на основе контекста

2. Просмотрите комментарии к каждому непройденному критерию (вкладка "Критерии")
3. Начните с критичных критериев — исправьте их в первую очередь
4. Исправьте README на основе комментариев
5. Проверьте снова
6. Повторяйте до тех пор, пока все критерии не будут пройдены

**Совет:** Обычно после 1-2 итераций исправлений все критерии проходят проверку. Система дает конкретные рекомендации, следуя которым вы быстро исправите все проблемы.

**Q: Что означает статистика в вкладке "Статистика текста"?**

A:
- **Количество слов/символов** — общий объем документа
- **Количество заголовков** — структура документа (должна быть логичной иерархией)
- **Средняя длина предложений** — показатель читаемости (слишком длинные предложения снижают читаемость)
- **Количество списков/таблиц/блоков кода** — разнообразие форматирования

**Как использовать:**
- Проверьте структуру заголовков — она должна быть логичной
- Обратите внимание на среднюю длину предложений — если она слишком большая, текст может быть сложным для чтения
- Убедитесь, что есть разнообразие форматирования (списки, таблицы, код)

### Вопросы об обратном извлечении

**Q: Как система определяет образовательные результаты и навыки?**

A:
Система использует несколько методов:
1. **Прямое извлечение** — если в README есть специальные разделы "Образовательные результаты" или "Навыки", данные извлекаются оттуда
2. **Анализ содержания** — система анализирует текст и определяет, что является образовательным результатом (знания), а что — навыком (умения)
3. **Использование ключевых слов** — система ищет характерные фразы и паттерны
4. **Искусственный интеллект** — если прямого извлечения недостаточно, система использует языковую модель для анализа текста

**Важно:** Система всегда показывает, как были определены LO и навыки, и может предложить новые тематические блоки, если найдет проекты, которые не соответствуют существующим категориям.

---

**Q: Что делать, если система предложила новый тематический блок?**

A:
- Если система обнаружила проект, который не соответствует существующим тематическим блокам, она предложит новый блок
- Вы можете:
  - Использовать предложенный блок (он будет добавлен в систему)
  - Выбрать существующий блок вручную (если считаете, что проект всё же относится к существующему блоку)
  - Игнорировать предложение (если оно не релевантно)

**Совет:** Предложения системы обычно обоснованы — если она предлагает новый блок, это может означать, что проект действительно не соответствует существующим категориям.

---

**Q: Можно ли извлечь данные из нескольких README сразу?**

A:
- В текущей версии системы обратное извлечение работает с одним файлом за раз
- Для массовой обработки можно:
  - Извлечь данные из каждого README по отдельности
  - Собрать все Excel-файлы в одну папку
  - Объединить их вручную или с помощью скрипта

**Совет:** Если у вас много проектов для обработки, обрабатывайте их последовательно и сохраняйте Excel-файлы в организованную структуру папок.

---

**Q: Что делать, если извлеченные данные неверны?**

A:
1. Проверьте исходный README — возможно, информация там указана неявно или нестандартно
2. Внесите корректировки в Excel-файл вручную
3. Используйте исправленный Excel-файл для дальнейшей работы
4. Если проблема повторяется, проверьте структуру README — возможно, её нужно улучшить

**Совет:** Система делает всё возможное для точного извлечения, но качество результата зависит от качества исходного README. Чем структурированнее README, тем точнее будет извлечение.

**Q: Можно ли использовать извлеченный Excel-файл для генерации нового проекта?**

A:
- Да! Это одна из основных целей обратного извлечения
- Загрузите Excel-файл в генератор через поле "Готовый JSON/Excel со спецификацией"
- Форма автоматически заполнится данными из файла
- Вы можете внести изменения, если нужно
- Запустите генерацию нового проекта

**Совет:** Это особенно полезно, когда нужно создать похожий проект или обновить существующий проект с новыми параметрами.
