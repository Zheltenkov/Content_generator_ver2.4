# Как определяются Learning Outcomes и Навыки

## Общий подход

Система использует **двухуровневый подход** для извлечения Learning Outcomes (LO) и навыков:

1. **Основной метод**: LLM с structured outputs (через `StructureExtractor`)
2. **Fallback метод**: Regex-паттерны и ключевые слова (если LLM не работает)

## Контекст использования

Извлеченные LO и навыки используются в двух режимах:

1. **Режим улучшения README** (основной): Данные передаются напрямую в пайплайн генерации для создания улучшенного README
2. **Режим создания Excel** (legacy): Данные сохраняются в Excel-шаблон спецификации проекта

---

## 1. Основной метод (LLM)

### Промпты для извлечения

**System prompt** (`content_gen/prompts/reverse_extraction/structure_extractor/system.md`):
- Эксперт по парсингу учебных проектов
- Задача: извлечь структурированные данные из README
- Язык ответа: русский или английский (в зависимости от README)

**User prompt** (`content_gen/prompts/reverse_extraction/structure_extractor/user_template.md`):

#### Learning Outcomes (LO):
```
3. **learning_outcomes**: Найди образовательные результаты (learning outcomes). 
   Если они явно не указаны, переформулируй их на основе содержания проекта:
   - Что студент должен научиться делать?
   - Какие знания и навыки он получит?
   - Какие результаты обучения достигаются?
```

LLM анализирует README и:
- Ищет явно указанные LO (например, в разделе "Образовательные результаты")
- Если не найдены явно, **переформулирует** их на основе:
  - Практических задач
  - Теоретического материала
  - Описания проекта

#### Skills (Навыки):
```
5. **skills**: Определи навыки, которые развивает проект. Проанализируй:
   - Практические задачи (что нужно уметь для их выполнения)
   - Теоретический материал (какие концепции изучаются)
   - Образовательные результаты
```

LLM определяет навыки на основе:
- Анализа задач (какие навыки нужны для их выполнения)
- Теоретического материала (какие концепции изучаются)
- Связи с образовательными результатами

### Модель данных

Результат возвращается в формате `PartialProjectSeed`:
```python
learning_outcomes: List[str]  # Список образовательных результатов
skills: List[str]             # Список навыков
```

## 2. Fallback метод (Regex + ключевые слова)

Если LLM не работает, используется fallback в `_fallback_extraction()`:

### Learning Outcomes (LO):

**Паттерны поиска:**
```python
lo_patterns = [
    # Паттерн 1: Явные указания на LO
    r'(?:После изучения|В результате|Студент научится|Студент сможет|Цель|Цели)[:.]?\s*([^.!?]+[.!?])',
    
    # Паттерн 2: Маркированные списки с заглавной буквы
    r'[-•]\s*([А-ЯЁ][^.!?]+[.!?])',
]
```

**Логика:**
1. Ищет в главах 1 и 2 README
2. Ищет фразы типа:
   - "После изучения..."
   - "В результате..."
   - "Студент научится..."
   - "Студент сможет..."
   - "Цель"/"Цели"
3. Ищет маркированные списки (начинающиеся с заглавной буквы)
4. Берет первые 3-5 найденных результатов

### Skills (Навыки):

**Ключевые слова:**
```python
skills_keywords = [
    'программирование', 'разработка', 'тестирование', 'деплой', 'развертывание',
    'база данных', 'api', 'frontend', 'backend', 'алгоритмы', 'структуры данных',
    'git', 'ci/cd', 'контейнеризация', 'мониторинг', 'логирование'
]
```

**Логика:**
1. Ищет упоминания ключевых слов в тексте README
2. Добавляет найденные навыки в список
3. Ограничивает до 10 навыков

## Проблемы и улучшения

### Текущие проблемы:

1. **Fallback метод слишком простой**:
   - Использует только ключевые слова для навыков
   - Не анализирует контекст
   - Может пропустить важные навыки

2. **LO извлекаются только по паттернам**:
   - Не переформулируются, если не найдены явно
   - Могут быть неполными

### Рекомендации для улучшения:

1. **Улучшить промпты для LLM**:
   - Добавить больше примеров
   - Уточнить критерии для LO и навыков
   - Добавить инструкции по переформулированию

2. **Улучшить fallback**:
   - Добавить больше паттернов для LO
   - Использовать NLP для извлечения навыков из контекста
   - Анализировать задачи для определения навыков

3. **Валидация результатов**:
   - Проверять, что LO соответствуют задачам
   - Проверять, что навыки логично связаны с проектом
   - Добавить минимальные требования (например, минимум 2 LO)

## Примеры

### Пример 1: Явные LO в README
```
## Образовательные результаты

После изучения проекта студент:
- Научится настраивать CI/CD пайплайны
- Освоит работу с Docker и контейнеризацией
- Поймет принципы мониторинга приложений
```

**Результат LLM:**
```python
learning_outcomes = [
    "Научится настраивать CI/CD пайплайны",
    "Освоит работу с Docker и контейнеризацией",
    "Поймет принципы мониторинга приложений"
]
```

### Пример 2: Неявные LO (переформулирование)
README содержит только описание задач, но не явные LO.

**LLM анализирует задачи и переформулирует:**
```python
learning_outcomes = [
    "Научится работать с базами данных PostgreSQL",
    "Освоит создание REST API на FastAPI",
    "Поймет принципы аутентификации и авторизации"
]
```

### Пример 3: Навыки из задач
```
## Задача 1: Создать API для управления пользователями
## Задача 2: Настроить Docker контейнеры
## Задача 3: Реализовать тесты
```

**LLM определяет навыки:**
```python
skills = [
    "Разработка REST API",
    "Работа с Docker",
    "Тестирование",
    "Работа с базами данных"
]
```

---

## Логирование

Для отладки можно проверить логи:
- `StructureExtractor: извлечено title='...', tasks_count=..., skills=...`
- `Fallback extraction: LO=..., tools=..., skills=...`

Если видите "Fallback extraction", значит LLM не сработал и используется простой метод.
